# Игровая аналитика

Три Яндекс-сборки используют выбранный владелицей счётчик **113771637**. Номер хранится в `yandex.config.json`; значение 0 при необходимости отключает загрузку тега и отправку. Личный профиль не включает тег даже при наличии номера. Для временной тестовой сборки есть YANDEX_METRICA_COUNTER; обычные CI-выпуски используют сохранённую конфигурацию.

## Подключение

1. Отдельный счётчик 113771637 выбран для трёх игр. Игра/уровень различаются параметрами событий.
2. В Метрике выключить ограничение «Принимать данные только с указанных адресов», поскольку игра открывается на домене платформы. Записать номер в yandex.config.json, пересобрать и загрузить оба игровых архива.
3. Создать цели типа «Целевое событие» с точным совпадением имён из таблицы ниже. Без соответствующей цели параметры reachGoal не попадут в нужный отчёт.
4. Открыть черновик с `_ym_debug=1`, пройти сценарии и проверить сообщения Reach goal. Тестовый сборщик в браузерной QA проверяет код, но не доказывает получение настоящим счётчиком.
5. Открыть отчёты Метрики или дать доступ к их выгрузке для анализа. Номер счётчика позволяет отправлять события, но сам по себе не даёт агенту доступ читать отчёты.

## События

В каждом событии есть `game.game` (sudoku/nonogram/wordsearch), `game.level`, группа сложности/размера, размер поля и версия. Параметры действия лежат в `event.<имя события>`.

| События | Что показывают |
|---|---|
| gameLevelStart, gameLevelComplete, gameLevelExit | Вход на уровень, победа, смена/перезапуск/завершение/уход страницы. Уход страницы может быть обновлением, это не доказательство отказа от игры. |
| gameProgress | Достижение 25, 50 и 75% правильного заполнения один раз за текущий запуск уровня. |
| gameActivity | Сводка частых действий каждые 10 секунд и при смене/завершении: нажатия функций, ввод чисел, пометки, ошибки, штрихи, закраска, крестики и очистка. |
| gameHintUsed | Новый оплаченный из баланса разбор, с названием логического приёма. Повторное чтение не создаёт ещё одно использование. Нажатия кнопки считаются отдельно в сводке. |
| gameCandidatesUsed | Использование расстановки или пересчёта кандидатов. |
| gameRoundPaused, gameRoundFinished, gameRoundRevived | Четвёртая ошибка и выбор игрока: закончить или восстановить партию. |
| gameTutorialStart, gameTutorialStep, gameTutorialComplete, gameTutorialSkip, gameTutorialDoubleTap | Начало, шаги и исход обучения; успешная тренировка двойного тапа. |
| gameRewardedRequest, gameRewardedOpen, gameRewardedEarned, gameRewardedClose, gameRewardedError | Реклама с наградой, с placement candidates/hints/revive. Earned следует успешной выдаче награды; закрытие и ошибка её не подтверждают. |
| gameFullscreenRequest, gameFullscreenOpen, gameFullscreenClose, gameFullscreenError | Межуровневая реклама японских, с признаком фактического показа. |

Активное время исключает диалоги, рекламу, скрытую вкладку и остановленную партию. После обновления страницы начинается новый отрезок наблюдения. Итоги действий при победе относятся к текущему отрезку, не ко всем предыдущим посещениям этой задачи.

В пользовательские параметры не передаются имена, почта, Яндекс ID, содержимое localStorage или полная сетка. Вебвизор и автоматическая карта кликов в конфигурации тега выключены. Сам сервис Метрики работает со своими обычными техническими данными и идентификаторами посещений; эти события не следует называть полностью анонимным каналом.

## Первые отчёты

- Воронка обучения: Start → DoubleTap → Complete для судоку; отдельно доля Skip.
- Прохождение по игре/сложности/уровню: LevelStart → Progress 50 → LevelComplete. Сравнивать число пользователей и число посещений, учитывая повторы и обновления.
- Помощь: число HintUsed на уровне, приёмы, доля использования кандидатов и число повторных пересчётов.
- Ошибки: доля RoundPaused, выбор Finished или Revived, последующая победа.
- Реклама: Request → Open → Earned отдельно по каждому placement. Callback не содержит рекламный доход; доход смотреть в кабинете Яндекса.
- Кнопки и японские: сводки gameActivity с количеством закрасок/крестиков/отмен, темп и этапы прогресса. По этим данным можно найти трудные уровни и непонятные функции.

## Ограничения

Это агрегаты, не запись каждой партии и не точное воспроизведение порядка клеток. Частые действия объединяются в сводки из-за ограничений целей Метрики: одна цель учитывается не чаще раза в секунду, а число достижений за посещение ограничено. Блокировщик, пропавшая сеть или закрытие страницы могут потерять данные; игра от этого продолжает работать. Показатели аналитики не заменяют сохранённый игровой прогресс.

Для повтора «клетка за клеткой» понадобится отдельный ограниченный журнал игровых ходов и место его приёма/просмотра. Такая запись в эту реализацию не входит.

Официальные руководства: [подключение и события](https://yandex.ru/dev/games/doc/ru/concepts/yandex-metrica), [рекламные события](https://yandex.ru/dev/games/doc/ru/concepts/metrica/sdk-events), [воронки и ограничения](https://yandex.ru/dev/games/doc/ru/concepts/metrica/reports).

Список целей для копирования: [metrica-goals.tsv](metrica-goals.tsv). Это таблица для ручного создания целей, не файл автоматического импорта. Начать с gameLevelStart, gameLevelComplete, gameActivity, gameHintUsed, gameRoundPaused, gameRoundRevived и целей обучения; затем добавить остальные. QA и запись медиа подменяют номер тестовым или нулём и блокируют обращения к настоящей Метрике.

В поиске слов передаются gameWordFound и gameWordRevealed с длиной слова и этапом поиска; полная сетка и последовательность букв не передаются. Для автоматического создания всех актуальных целей использовать [API-загрузчик](metrica-api.md). Ручное создание каждой цели не требуется при доступном OAuth.

Подсказка начальной буквы использует gameHintUsed с technique=word-initial, буквой и признаком расхода spent; повторные включения идут только в сводку initial_highlight. Новые определения целей не требуются. Полная сетка по-прежнему не передаётся.

С 1.4.1 level сохраняет стабильный идентификатор задачи, levelNumber передаёт номер, видимый игроку. При разборе скриншота/меню использовать levelNumber: порядок судоку теперь непрерывный по сложности.

Пакетный ввод из всех одиночных пометок попадает в gameActivity как finish_from_notes, число вписанных цифр — digit_input. Новых целей не требуется, gameHintUsed не вызывается и баланс помощи не меняется.
