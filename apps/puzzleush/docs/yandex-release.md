# Выпуск в Яндекс Игры

Две отдельные игры собираются из общих исходников с личным сайтом. `npm run build:yandex` из `apps/puzzleush` создаёт `build/yandex/kletochki-sudoku-1.2.2.zip` и `kletochki-nonogram-1.2.2.zip`. У каждого index.html в корне, размер меньше 100 МБ; источник всех движков подтверждается одинаковым `sharedHash` в release.json. Корневой build.sh собирает эти архивы при каждом выпуске сайта; Pages workflow сохраняет их отдельным артефактом `kletochki-yandex`. Автоматической загрузки в кабинет нет.

## Что нужно сделать владелице

1. Открыть [консоль разработчика](https://games.yandex.ru/console/) со своим Яндекс ID, заполнить сведения разработчика и принять договор. Это действие с личными юридическими данными выполняет владелица аккаунта.
2. Создать два черновика: «Клеточки: Судоку с объяснениями» и «Клеточки: Японские кроссворды». В каждый загрузить соответствующий игровой ZIP, а не весь комплект материалов. Если название уже занято в каталоге, перед публикацией синхронно изменить название и материалы.
3. Заявить русский язык, десктоп и мобильные устройства. Первую публикацию телефона настроить в портретной ориентации; альбомная вёрстка дополнительно проверена в Chromium. iOS/Safari перед заявлением платформы проверить на реальном устройстве или браузере. ТВ не заявлять. Облачных сохранений и покупок нет. Вход в аккаунт игрока не обязателен.
4. Включить монетизацию и видеорекламу с наградой. В японских включить полноэкранную рекламу. Sticky-баннеры оставить выключенными: макет под них не отводит место. В судоку восстановление после четвёртой ошибки — добровольный просмотр с наградой, не автоматическая реклама поверх ввода.
5. Скопировать тексты из [карточек каталога](yandex-catalog.md). Из каталога `yandex-media/<игра>/` загрузить icon-512.png, cover-800x470.png, два mobile-*.png, два desktop-*.png и gameplay-16x9.mp4. onboarding-preview.png — дополнительный предпросмотр обучения, в скриншоты геймплея его не включать.
6. Открыть оба черновика с debug-панелью SDK и выполнить проверки ниже. После успешной проверки отправить на модерацию. При желании включить отсроченную публикацию, чтобы отдельно открыть публичный доступ после модерации.

## Реальная проверка в черновике

Локальная QA использует тестовые callbacks SDK. Она проверяет нашу логику, но не доказывает загрузку настоящего `/sdk.js`, доступность рекламы или принятие игры платформой. До создания кабинета этот шаг не выполнен.

- Game Ready приходит после загрузки шрифтов и доступного интерфейса, включая обучение. Gameplay start/stop соответствуют полю, диалогам, паузе вкладки и рекламе.
- В Яндекс-судоку завершить rewarded-просмотр для кандидатов: текущий уровень открыт, повторный пересчёт и перезагрузка не требуют второй рекламы. На другом уровне доступ отдельный.
- Просмотр подсказок даёт ровно 3. Открытие нового полезного разбора расходует 1, повторное чтение того же поля бесплатно. Диагностика противоречия бесплатна. Подсказка не вводит ответ.
- Закрытие/ошибка/отсутствие рекламы не выдаёт награду и не блокирует ручное решение. Повторные callbacks не удваивают начисление.
- Сделать три неверных ввода — партия продолжается. На четвёртом блокируется. Перезагрузка не снимает блокировку. Отмена и стирание не возвращают ошибки. Подтверждённая реклама сохраняет поле и даёт новый лимит; закрытие рекламы оставляет выбор. «Завершить партию» сохраняет достижения и разрешает другую задачу. Новый старт текущей задачи явно начинает новую попытку.
- Японские не показывают рекламу в процессе рисования или сразу по победе; запрос происходит после нажатия «Следующий уровень». Если показ не состоялся из-за частоты/ошибки, переход всё равно работает.
- Прогресс, баланс, попытка и флаг обучения переживают обновление вкладки. Очистка браузерных данных их удаляет. Сохранения личного сайта и двух Яндекс-игр разделены.
- Язык берётся из `environment.i18n.lang`; единственная заявленная локализация ru служит запасной для других языков. Не заявлять английский до перевода интерфейса и материалов.
- Мобильный экран не прокручивает страницу и не вызывает pull-to-refresh; большие японские перемещаются внутри игрового viewport. Проверить реальное устройство, поворот, правую кнопку мыши, масштаб и свайп.

## Подготовка и проверки локально

```sh
npm test
npm run build:yandex
# Сервер только для локальной проверки. Настоящий SDK проверяется в черновике.
python3 -m http.server 4337 --bind 127.0.0.1 --directory .
# В другом терминале, с Playwright и Chromium из среды:
node scripts/browser-yandex-qa.mjs
node scripts/yandex-media.mjs
```

QA_ORIGIN, PLAYWRIGHT_MODULE, BROWSER_EXECUTABLE и FFMPEG можно задать переменными среды. В распространяемые архивы тестовая реализация SDK не копируется. Шрифты локальны; OFL-лицензии лежат рядом с ними. Результаты QA — test-results/yandex/qa.json, материалы — build/yandex-media/. Видео снимается с игрового интерфейса с тестовыми SDK-ответами; настоящая реклама не записывается.

## Обновление и откат

Менять только общие dist/ и движки. Увеличить версию, собрать и проверить все профили; для кабинета заново загрузить оба ZIP, если общее игровое поведение изменилось. Личный сайт остаётся без SDK и рекламы. Сохранить предыдущие архивы для отката. Не менять содержимое/порядок уровней без миграции и не удалять ключи localStorage. Возврат архива не требует сброса прогресса.

Проверенные требования: [подключение SDK](https://yandex.ru/dev/games/doc/ru/sdk/sdk-about), [готовность и геймплей](https://yandex.ru/dev/games/doc/ru/sdk/sdk-game-events), [реклама](https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv), [поля и размеры материалов](https://yandex.ru/dev/games/doc/ru/console/add-new-game/draft), [загрузка игры](https://yandex.ru/dev/games/doc/ru/console/add-new-game).

Аналитика настраивается отдельно: [схема событий и выбор счётчика](analytics.md). В yandex.config.json выбран счётчик 113771637. Создать цели из docs/metrica-goals.tsv в кабинете Метрики и проверить `_ym_debug=1` в черновике. Для отключения отправки задать номер 0 и пересобрать ZIP. Не включать автоматическую запись экрана ради базовых событий.
