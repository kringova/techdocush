# Выпуск в Яндекс Игры

Три отдельные игры собираются из общих исходников с личным сайтом. `npm run build:yandex` из `apps/puzzleush` создаёт `build/yandex/kletochki-sudoku-1.5.0.zip`, `kletochki-nonogram-1.5.0.zip` и `kletochki-wordsearch-1.5.0.zip`. У каждого index.html в корне, размер меньше 100 МБ; источник всех движков подтверждается одинаковым `sharedHash` в release.json. Корневой build.sh собирает эти архивы при каждом выпуске сайта; Pages workflow сохраняет их отдельным артефактом `kletochki-yandex`. Автоматической загрузки в кабинет нет.

## Что нужно сделать владелице

1. Открыть [консоль разработчика](https://games.yandex.ru/console/) со своим Яндекс ID, заполнить сведения разработчика и принять договор. Это действие с личными юридическими данными выполняет владелица аккаунта.
2. Создать три черновика: «Клеточки: Судоку с объяснениями», «Клеточки: Японские кроссворды» и «Клеточки: Поиск слов». В каждый загрузить соответствующий игровой ZIP, а не весь комплект материалов. Если название уже занято в каталоге, перед публикацией синхронно изменить название и материалы.
3. Заявить русский язык, десктоп и мобильные Android/iOS. Первую публикацию телефона настроить в портретной ориентации; альбомная вёрстка дополнительно проверена в Chromium. До отправки на модерацию проверить настоящий iPhone/Safari и Android; настольная эмуляция не заменяет эту проверку. ТВ не заявлять. Облачных сохранений и покупок нет. Вход в аккаунт игрока не обязателен.
4. Включить монетизацию и видеорекламу с наградой. В японских и поиске слов включить полноэкранную рекламу. Sticky-баннеры оставить выключенными: макет под них не отводит место. В судоку восстановление после четвёртой ошибки — добровольный просмотр с наградой, не автоматическая реклама поверх ввода.
5. Скопировать тексты из [карточек каталога](yandex-catalog.md). Из каталога `media/<игра>/` в комплекте (в исходниках `build/yandex-media/<игра>/`) загрузить icon-512.png, cover-800x470.png, два mobile-*.png, два desktop-*.png и gameplay-16x9.mp4. onboarding-preview.png — дополнительный предпросмотр обучения, в скриншоты геймплея его не включать.
6. Открыть все черновики с debug-панелью SDK и выполнить проверки ниже. После успешной проверки отправить на модерацию. При желании включить отсроченную публикацию, чтобы отдельно открыть публичный доступ после модерации.

## Реальная проверка в черновике

Локальная QA использует тестовые callbacks SDK. Она проверяет нашу логику, но не доказывает загрузку настоящего `/sdk.js`, доступность рекламы или принятие игры платформой. До создания кабинета этот шаг не выполнен.

## Полный комплект загрузки

По умолчанию к каждой публикации или обновлению готовить все ответы и файлы сразу. Канонические тексты — `docs/yandex-catalog.md`. Форма Яндекса меняется: перед новым комплектом сверить [официальные поля](https://yandex.ru/dev/games/doc/ru/console/add-new-game/draft), ограничения и обязательность материалов.

Из каталога приложения:

```sh
npm run build:yandex
# В отдельном терминале — локальный сервер, доступный только этому компьютеру:
python3 -m http.server 4337 --bind 127.0.0.1 --directory .
# PLAYWRIGHT_MODULE / BROWSER_EXECUTABLE / FFMPEG задаются из среды при необходимости.
node scripts/yandex-media.mjs
# Указать дату реальной сверки требований; FFPROBE или --ffprobe задают путь при необходимости.
python3 scripts/build-yandex-upload-kit.py --requirements-checked YYYY-MM-DD
```

Результат — `build/yandex-upload-<версия>/` и одноимённый ZIP. Для сохранения прямо в Downloads передать `--output /полный/путь/новая-папка`. Существующий комплект не перезаписывается. Старые выпуски сохранять.

Открыть `START-HERE.html`: локальная страница без сетевых запросов с кнопками копирования, параметрами всех карточек и точным соответствием файлов полям. Поля следуют порядку Консоли: ключевые слова/облако/отсрочка/комментарий, затем название/SEO/об игре/короткое/как играть, иконка/обложка, видео, скриншоты, рекламное видео и AI-описания. В каждой папке — игровой ZIP, семь текстовых полей, `answers.txt`, `form.json`, иконка/обложка/видео в `media/`, отдельные `screenshots-desktop-16x9/` и `screenshots-mobile-9x16/`, обучение в `extras/`. В «Десктопные» загружать desktop1/2, в «Мобильные» → «Портретная» mobile1/2; ошибка16:9 для мобильного файла означает неверный тип/ориентацию поля. Большой ZIP комплекта сначала распаковать, загружать внутренний ZIP нужной игры.

Проверки сборщика: длины всех текстов; целостность ZIP и его ресурсов; совпадение dist/трёх профилей; совпадение медиа по версии/sharedHash и SHA256; PNG512×512/800×470; по два RGB-скриншота16:9/9:16 с длинной стороной1280–2560; горизонтальный H264MP4/yuv420p16:9, высота≥400, длительность≤28с, размер≤100МБ. `media-release.json` записывается после полной съёмки; режим ASSETS_ONLY не создаёт новое подтверждение полного набора. Перед кадром требуется исчезновение класса visible и завершение fade-out toast, а не только начальная opacity0.

Проверка сборщика: `python3 -m unittest discover -s tests -p 'test_yandex_upload_kit.py'`, входит также в корневой build.sh. Пакет содержит `MANIFEST.json` с результатами/контрольными суммами и `CHECK-BEFORE-MODERATION.txt`. Готовность файлов не означает успешную настоящую рекламу, проверку iPhone или прохождение модерации.

Теги — только подходящие варианты из текущего списка Консоли, рекомендации не являются идентификаторами API. Только русский язык, английскую вкладку и AI-описания отключить; облачные сохранения, денежные товары и sticky-баннеры не заявлять. Необязательные вертикальное/рекламные видео, GIF, maskable и обложку на витрину можно оставить пустыми. Реквизиты и договор заполняются у Яндекса, без копирования в комплект. Использовать существующий черновик игры, не плодить дубликаты. Новый аккаунт может иметь лимит одной заявки новой игры на модерации.

- Game Ready приходит после загрузки шрифтов и доступного интерфейса, включая обучение. Gameplay start/stop соответствуют полю, диалогам, паузе вкладки и рекламе.
- В Яндекс-судоку завершить rewarded-просмотр для кандидатов: текущий уровень открыт, повторный пересчёт и перезагрузка не требуют второй рекламы. На другом уровне доступ отдельный.
- Просмотр подсказок даёт ровно 3. Открытие нового полезного разбора расходует 1, повторное чтение того же поля бесплатно. Диагностика противоречия бесплатна. Подсказка не вводит ответ.
- Закрытие/ошибка/отсутствие рекламы не выдаёт награду и не блокирует ручное решение. Повторные callbacks не удваивают начисление.
- Сделать три неверных ввода — партия продолжается. На четвёртом блокируется. Перезагрузка не снимает блокировку. Отмена и стирание не возвращают ошибки. Подтверждённая реклама сохраняет поле и даёт новый лимит; закрытие рекламы оставляет выбор. «Завершить партию» сохраняет достижения и разрешает другую задачу. Новый старт текущей задачи явно начинает новую попытку.
- Японские не показывают рекламу в процессе рисования или сразу по победе; запрос происходит после нажатия «Следующий уровень». Если показ не состоялся из-за частоты/ошибки, переход всё равно работает.
- Прогресс, баланс, попытка и флаг обучения переживают обновление вкладки. Очистка браузерных данных их удаляет. Сохранения личного сайта и трёх Яндекс-игр разделены.
- Язык берётся из `environment.i18n.lang`; единственная заявленная локализация ru служит запасной для других языков. Не заявлять английский до перевода интерфейса и материалов.
- Мобильный экран не прокручивает страницу и не вызывает pull-to-refresh; большие японские перемещаются внутри игрового viewport. Проверить реальное устройство, поворот, правую кнопку мыши, масштаб и свайп.

## Подготовка и проверки локально

```sh
npm test
npm run build:yandex
# Сервер только для локальной проверки. Настоящий SDK проверяется в черновике.
python3 -m http.server 4337 --bind 127.0.0.1 --directory .
# В другом терминале, с Playwright и Chromium из среды:
node scripts/browser-yandex-qa.mjs
node scripts/yandex-media.mjs
```

QA_ORIGIN, PLAYWRIGHT_MODULE, BROWSER_EXECUTABLE и FFMPEG можно задать переменными среды. В распространяемые архивы тестовая реализация SDK не копируется. Шрифты локальны; OFL-лицензии лежат рядом с ними. Результаты QA — test-results/yandex/qa.json, материалы — build/yandex-media/. Видео снимается с игрового интерфейса с тестовыми SDK-ответами; настоящая реклама не записывается.

## Обновление и откат

Менять только общие dist/ и движки. Увеличить версию, собрать и проверить все профили; для кабинета заново загрузить все три ZIP, если общее игровое поведение изменилось. Личный сайт остаётся без SDK и рекламы. Сохранить предыдущие архивы для отката. Не менять содержимое/порядок уровней без миграции и не удалять ключи localStorage. Возврат архива не требует сброса прогресса.

Проверенные требования: [подключение SDK](https://yandex.ru/dev/games/doc/ru/sdk/sdk-about), [готовность и геймплей](https://yandex.ru/dev/games/doc/ru/sdk/sdk-game-events), [реклама](https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv), [поля и размеры материалов](https://yandex.ru/dev/games/doc/ru/console/add-new-game/draft), [загрузка игры](https://yandex.ru/dev/games/doc/ru/console/add-new-game).

Аналитика настраивается отдельно: [схема событий и выбор счётчика](analytics.md). В yandex.config.json выбран счётчик 113771637. Создать цели из docs/metrica-goals.tsv в кабинете Метрики и проверить `_ym_debug=1` в черновике. Для отключения отправки задать номер 0 и пересобрать ZIP. Не включать автоматическую запись экрана ради базовых событий.

## Поиск слов

Третья карточка получает games/kletochki-wordsearch-1.5.0.zip. Видеореклама с наградой даёт три подсказки: одна раскрывает слово либо открывает подсветку всех экземпляров его первой буквы. Повторное включение открытой буквы уровня бесплатно. Межуровневая реклама — после победы при явном переходе. Проверить перетаскивание, два касания, клавиатуру, раскрытие без зачёта находки, подсветку всех начальных букв, однократный расход/бесплатное повторение и сохранение после обновления. Цели можно загрузить одним запуском scripts/metrica-goals.mjs --apply после получения OAuth, см. [API](metrica-api.md). Сохранения v3 переносят старые игры, v1/v2 остаются нетронутыми.

С версии 1.4 судоку 130, японские/слова 30. Проверить переносprogress-v3→progress-v4 со всеми 30 прежними судоку, сохранение баланса и кандидатов, продолжение нового эксперта 81 и последний 130. Старые ключи не удалять. Локальная проверка: scripts/browser-sudoku-expansion-qa.mjs.

В 1.5.0 основной экран не прокручивается; низкие portrait/landscape окна размещают управление сбоку. Японские по умолчанию целиком: проверить 10/15/20 с числами, последнюю клетку, undo, добровольный + и возврат «Всё поле». Меню уровней/список слов имеют внутреннюю прокрутку. Дополнительный прогон: scripts/browser-viewport-qa.mjs (включая 20% сокращение высоты). Реальный iframe портала и устройства остаются проверкой в черновике, локальный Chromium их не заменяет.

Судоку1.5: проверить «Заполнить всё» лишь при одиночных пометках во всём остатке, ввод/undo, отмену эффекта сменой уровня, reduced-motion и отсутствие расхода подсказок/рекламы. Остановленная партия не обходится. browser-finish-qa.mjs выполняется в CI; viewport-qa проверяет экраны с видимой новой кнопкой.
