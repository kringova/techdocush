# Загрузка целей через API Метрики

Официальный API позволяет создать все игровые цели без отдельных форм. Для счётчика 113771637 нужен OAuth-токен аккаунта с доступом к этому счётчику и правами `metrika:read` / `metrika:write`. Фрагмент установки `ym(...)` содержит только номер и не предоставляет этот доступ.

Готовый CLI: `scripts/metrica-goals.mjs`. Источники определений — `GAME_EVENTS` в общем игровом модуле и русские подписи `docs/metrica-goals.tsv`. Число игр или событий не зашито в загрузчик: новые события попадут в синхронизацию после обновления таблицы подписей.

## Один раз разрешить доступ

1. В аккаунте владелицы открыть [создание OAuth-приложения](https://oauth.yandex.ru/client/new) и выбрать вариант **«Для доступа к API или отладки»**.
2. Задать имя, например «Клеточки — аналитика», контактную почту и доступы **metrika:read** и **metrika:write**. Другие доступы для этой задачи не нужны.
3. Если форма просит Redirect URI для ручного получения токена, указать `https://oauth.yandex.ru/verification_code`.
4. Скопировать **ClientID** приложения. Это публичный идентификатор; его можно передать агенту, чтобы получить готовую ссылку авторизации. Client Secret для этого сценария не нужен.
5. Открыть ссылку `https://oauth.yandex.ru/authorize?response_type=token&client_id=CLIENT_ID`, подставив свой ClientID. Проверить аккаунт и список запрашиваемых прав и подтвердить доступ.
6. Выданный OAuth-токен вставить **в скрытый локальный ввод** команды ниже либо сохранить в отдельном файле вне репозитория с правами 600. Токен не отправлять в чат, не добавлять в Git и не размещать в игровом архиве.

Создание приложения и подтверждение доступа выполняет владелица аккаунта. После этого агент может сделать сверку и загрузить все цели одним запуском; ручное создание каждой цели не требуется. Локального перехвата браузерных cookies или использования чужих OAuth-приложений здесь нет.

## Проверить и загрузить

Из каталога `apps/puzzleush`:

```sh
# Показать все определения, без токена и без сети.
node scripts/metrica-goals.mjs --list-desired

# Скрытый ввод в обычном локальном терминале. По умолчанию только GET и план.
node scripts/metrica-goals.mjs --prompt-token

# Скрытый ввод и создание отсутствующих целей.
node scripts/metrica-goals.mjs --prompt-token --apply
```

Если токен уже хранится безопасно вне Git, агент может воспользоваться им напрямую:

```sh
node scripts/metrica-goals.mjs --token-file "$HOME/.config/puzzleush/metrica-token"
node scripts/metrica-goals.mjs --token-file "$HOME/.config/puzzleush/metrica-token" --apply
```

Путь должен находиться вне репозитория; файл — обычный, доступный только владельцу (600). Альтернативы: переменная `YANDEX_METRICA_TOKEN` или `--token-stdin` для существующего защищённого канала ввода. Токен не принимается аргументом командной строки и не печатается. Не помещать его буквальное значение в shell-команду или историю терминала.

Номер по умолчанию берётся из `yandex.config.json`; при необходимости его задаёт `--counter 113771637`. `--apply` — явное включение записи в API; без него CLI только читает список и показывает недостающие цели.

## Что делает синхронизация

- Читает список целей выбранного счётчика.
- Сопоставляет события с целями типа `action`, у которых ровно одно условие `{type:"exact", url:"имяСобытия"}`.
- Сохраняет уже существующие точные цели, включая их пользовательские названия.
- При совпадении названия или идентификатора с другими условиями останавливается до создания, вместо изменения чужой настройки.
- Перед каждым POST перечитывает список, после него независимо проверяет появление цели. Существующие цели не удаляет и не редактирует.
- Если POST завершился тайм-аутом или потерянным ответом, сначала перечитывает сервер. Подтверждённую цель засчитывает; если результат остался неизвестным, останавливается без повторного POST. Следующий запуск начинает со сверки и безопасно пропускает появившуюся цель.
- Выводит JSON с режимом, найденными/созданными/недостающими целями и конфликтами. Текст ответа сервера, заголовок авторизации и сетевые исключения с возможным секретом в вывод не попадают.

Успешный повторный запуск должен показать `missing: []` и `created: []`. После реальной загрузки проверить события в черновиках Яндекс Игр с `_ym_debug=1` и затем отчёты. Подготовка и mock-тесты не являются подтверждением, что цели уже созданы на настоящем счётчике.

Проверка загрузчика: `node --test tests/metrica-goals.test.mjs`. Тесты моделируют существующие/чужие цели, повторный запуск, параллельное появление, потерянный ответ, задержку видимости и недоступный API; внешние записи не выполняются.
