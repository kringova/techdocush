# Клеточки / puzzleush

- Для публикации в Яндекс Играх сразу готовить полный комплект по форме, а не только игровой ZIP: параметры, теги/ключевые слова/комментарий, все описания, иконка/обложка, обязательное горизонтальное видео и по два скриншота телефона/компьютера. Порядок полей и разделов HTML должен совпадать с Консолью; все загружаемые картинки/видео всех игр — в одной общей папке media, без подпапок; имена содержат игру/назначение/пропорции, HTML явно указывает тип/ориентацию скриншотов. `docs/yandex-release.md` описывает сборщик и проверку. Медиа обязаны совпадать с версией и sharedHash, временные уведомления не должны попадать в скриншоты.
- Целевые платформы — Десктоп, Android и iOS. Непроверенный реальный iPhone отмечать как предстоящую проверку перед модерацией; не исключать iOS молча. Сторонние способы публикации сначала проверять по условиям платформы, правам и передаче данных; не передавать сессию непроверенным посредникам.

Статический сайт: судоку, японские кроссворды и поиск слов. Владелица — Катя. Документация и задачи: личный Огород, projects/puzzleush.

- Исходники приложения в dist/, алгоритмы в dist/engine/; сборка не требуется.
- Проверки: npm test. Браузерная QA: scripts/browser-qa.mjs.
- Приоритет — мобильный экран от 360 px, управление касанием и доступные подписи.
- Подсказки судоку объясняют логику и не заполняют ответ автоматически.
- Двойной клик/тап — явное действие игрока: вписать единственную допустимую пометку. Заполненная клетка этим жестом не очищается; ход отменяется.
- Любая сложность и любой уровень доступны сразу. Базовых судоку пять; японских 5×5 — пять, затем 10×10, 15×15 и 20×20.
- Верно закрашенная строка/колонка японского кроссворда автоматически получает крестики; весь штрих с ними составляет один отменяемый ход.
- Обычные цифры в судоку — нейтральные тёмные. Выбор клетки и режим пометок не окрашиваются как ошибка; красный используется для неверного введённого числа, включая отсутствие повторов. Проверять по единственному решению, не окрашивать верные пользовательские записи.
- Любой добавляемый уровень должен иметь единственное решение. Проверки уникальности и объяснений обязательны.
- Прогресс хранится в localStorage, схема версионирована; не удалять существующий прогресс при обновлении.
- Текущая схема v4 использует новый ключ; v1, v2 и v3 сохраняются без изменений для восстановления. Нумерацию/содержимое уровней меняют только с явным соответствием старых и новых задач.
- Размещение и откат: docs/runbook.md. Игры публикуются на ringova.com/play/ через существующий Pages workflow.
- Не добавлять новые игры без запроса. Текущий состав: судоку, японские кроссворды и поиск слов.

- Все изменения игровой логики и задач должны попадать в личную версию и три сборки Яндекса из одного исходника. Не поддерживать отдельные копии движков. Корневой build.sh собирает все профили.
- Личный сайт всегда без SDK, рекламы и лимита ошибок. Только Яндекс: кандидаты уровня и +3 подсказки за подтверждённую рекламу; первые три ошибки разрешены, на четвёртой восстановление за рекламу или завершение. Баланс и ошибки не входят в undo.
- Game Ready, Gameplay API и паузы обязательны; награды только через onRewarded (совместимый onReward — тот же once-обработчик), не через закрытие. SDK-моки только в тестах.
- Первый запуск Яндекса обучает всем функциям; двойной тап тренируется вне поля. Обучение можно пропустить и открыть заново.
- Настоящие ответы SDK и рекламу проверять в черновике кабинета Яндекса; тестовые callbacks не доказывают работу живого рекламного сервиса. Инструкция: docs/yandex-release.md.
- Аналитика Яндекса включается только выбранным номером счётчика в yandex.config.json. Не подставлять автоматически счётчик личного сайта и не добавлять тег в личную игру. Ошибки аналитики не влияют на помощь/награды. Частые действия агрегировать; не обещать точную запись партий через цели Метрики.

- В поиске слов сначала видны тема и количество. Одна подсказка раскрывает слово; отдельная «Буква» выделяет все совпадения первой буквы раскрытого слова на поле. Не показывать только правильную стартовую клетку и не засчитывать слово. Новая буква Яндекс-уровня расходует один кредит, повторная активация бесплатна; история отмены не возвращает расход и не стирает помощь. Поддерживать выделение пальцем/мышью, два касания и клавиатуру. Все целевые слова в каждой сетке должны иметь по одному прямому размещению.
- Для массовой загрузки целей использовать scripts/metrica-goals.mjs; по умолчанию dry-run, запись --apply только для выбранного счётчика с полученным OAuth. Не выводить токены и не включать их в Git/архивы. Готовый код счётчика не является OAuth-доступом.

- Судоку 130: прежние 1–30 сохранять побайтно по fixtures/sudoku-1.3.1-hashes.json. Новые средние 31–50, сложные 51–80, эксперты 81–130; группы задаются chapterLevels, число задач — levelCount. Не считать start/end полным составом расширенной группы. Новые данные в additional-sudoku.js создаются офлайн, не на телефоне. При переносе v3→v4 сохранять все старые игры и оплаченные доступы benefits-v1.

- Японские 10×10+ по умолчанию целиком: сетка/числа масштабируются вместе; расширенный режим только по явному +. При смене уровня возвращать обзор. Яндекс: проверять границы кнопок и самого поля, а не только scrollHeight корня; scripts/browser-viewport-qa.mjs обязателен в Pages CI.

- «Заполнить всё» в судоку — только для всего остатка: у каждой пустой клетки ровно одна видимая пометка, весь предложенный набор валиден. Никогда не заполнять лишь часть одиночек и не искать ответ. Один снимок отмены, без списания помощи; paused-партия Яндекса не обходится. Анимация отменяется при renderBoard, reduced-motion не ждёт эффектов.

- Яндекс1.6: компактная панель вместо витрины, без логотипа/дублирующей пройденности/точек/инструкций; все функции доступны в управлении/меню/обучении. Штатный sticky настраивается в Консоли справа на десктопе/снизу на телефоне, показ платформой. Не добавлять в игру фальшивый рекламный контейнер или фиксированный отступ, если место уже выделено порталом. Проверять появление/скрытие области через browser-banner-qa.mjs; все размеры QA являются стресс-сценариями, не фактическими размерами баннера.
